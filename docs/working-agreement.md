# Working agreement

> Draft proposal. The team should read, change and agree on this together.

## Branches

- `main` is protected. Nobody pushes directly to it.
- Branch names: `feature/<short-name>`, `fix/<short-name>`, `docs/<short-name>`.

## Pull requests

- Every change goes through a pull request.
- At least one teammate reviews before merging.
- Keep pull requests small and focused.

## Board and issues

- One issue per task. Every task lives on the kanban board.
- Columns: Backlog, In progress, In review, Done.
- Assign yourself to an issue before you start.

## Communication

- Short check-in: <!-- when and where? -->
- Ask for help early.
